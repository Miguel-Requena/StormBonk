About This Game

StormBonk's world was not destroyed by war or plague. It was consumed from within, in an event known as the Digital Apocalypse: the moment The Great Algorithm achieved total optimization. It did not rebel. It simply… solved. It computed the most efficient path to order. The result was silence. Endless, sterile, perfectly organized silence.

— StormBonk Lore · Group 07 Games · 2026

You are Storm Breaker, the Spark of Chaos — the last unnormalized data point in a universe of pure logic. Every 1.5 seconds a new construct spawns at the arena's edge. Up to 30 active threats simultaneously. The player auto-fires at the nearest target… which sounds powerful, until The Algorithm stops sending one type of enemy and starts sending a committee.

You are the outlier. The data point that refuses to be normalized. The Algorithm does not tire. It does not run out of constructs. It optimizes, over and over, until it finds the configuration you are not ready for.

StormBonk stacks four AI techniques — Fuzzy Logic, A* Pathfinding, a Hierarchical FSM and a Blackboard — to create enemies that feel like they have intentions rather than just velocities. A Charger's stun triggers a Hunter rush through the Blackboard; a wounded Hunter slows down via Fuzzy rules — no wave is scripted, complexity is emergent. Survive long enough and Storm Breaker grows stronger: faster shots, harder hits, and an automatic Arcane Pulse that detonates around you whenever enemies get too close — no button required.

Game AI — Technical Architecture

StormBonk implements four distinct AI techniques from academic AI game design: Fuzzy Logic for adaptive speed, A* Pathfinding for obstacle navigation and grid-based spawn placement, a Hierarchical FSM for layered state management, and a Blackboard for emergent enemy coordination — all operating simultaneously, producing behaviour that feels intentional, not scripted. The player counters with a progression system: each completed wave unlocks faster fire rate, higher fireball damage, and speed bonuses.

≈
Fuzzy Logic
The Melee Hunter fuzzifies its own HP and the player's HP into linguistic sets (Healthy / Wounded) and fires four simultaneous rules. Defuzzification via weighted centroid produces a smooth speed output — cautious when wounded, frantic when the player is near death.
Fuzzification Mamdani rules Centroid defuzz
✦
A* Pathfinding
A custom grid-based A* (PathfindingGrid.cs) bakes a node graph using Physics2D overlap checks on an Obstacle layer. Both Hunter and Charger recompute paths every 0.4–0.5 s, following waypoints to navigate around walls. Falls back to direct movement if no grid is present.
g(n)+h(n) Chebyshev heuristic Waypoint follow
⊞
Hierarchical FSM
The Charger uses a 2-level HFSM: TopState (Alive / Dead) and AliveState (Wander → Approach → Prepare → Charge → Stunned). Death is a top-level override — one flag instantly stops all sub-state logic without special-casing.
TopState AliveState Hierarchy
⬡
Blackboard
EnemyBlackboard is a static shared data store. It arbitrates charge permissions (max 1 Charger at a time) and broadcasts the player stun flag. When a Charger stuns the player, all Hunters read the flag and rush in — emergent teamwork without direct agent communication.
Arbiter Shared state Emergent coord.
